## Product and master-data rules

The protected categories remain exactly `mobile_phone`, `tablet`, `accessory`. Category creation, archival and deletion through generic lifecycle operations are rejected. Labels/order/visibility can change independently of internal category codes. Subcategories require their protected parent category. Canonical unit-status and buying-source options cannot be permanently deleted; inactive/archived options remain available to existing references but cannot be selected for new references.

Product writes require fresh `shop.inventory` authorization and assigned/open outlet access; Website owner authority does not grant POS inventory authority. Master-data configuration uses the independent configuration grant. The low-level reused `PosMasterData`/`PosInventoryMasterData` helpers assume a trusted caller; external/UI adapters must use the authorized application services, never expose these helpers directly or accept actor metadata from a request.

`ProductDefinitions::save` creates a zero-stock definition or edits the identified product in the authorized outlet. Name uniqueness remains scoped to non-deleted products in that outlet. Device brands must be managed; model, RAM/storage, SIM, subcategory and warranty metadata retain source validation. Accessories clear device capacity/SIM references and never become IMEI-tracked. Stock counters, opening stock, public/business identifiers and actor/outlet IDs are not accepted as input fields. Money accepts exact non-negative decimal strings, rejects float/exponent/overprecision input and fits the existing `DECIMAL(19,2)` contract.

`unitAttributes` changes only managed color/condition/PTA/carrier/MDM attributes of an in-stock unit in the authorized outlet. It cannot set stock status, quantity, cost, IMEI or financial relationships. Product/unit and selected option rows are locked; the latest option lifecycle state is rechecked before usage writes. Existing holds block definition/attribute changes. Category/tracking-mode changes with stock or unit history require reconciliation instead of silently rewriting inventory. These are definition safeguards, not acceptance of the future reservation/stock transaction implementation.

New product/unit codes reuse the source `MST-{MOB|TAB|ACC}-{OUTLET3}-{sequence}` and `-U{unit_no}` formatting, allocated from database identities rather than `MAX+1`. Imported codes are retained unchanged. Invalid OUTLET3 values and unknown category-to-identifier mappings fail explicitly instead of silently generating a mobile code. Model attempts to change an existing code raise an error; callers cannot treat a silently discarded change as success.

Master-data label edits never rewrite raw product/unit attribute snapshots, old codes or order-item titles. Variant grouping continues to use the original raw values, including distinct blank/unknown semantics. `ProductProjection` exposes explicit public metadata/variant allowlists, excluding cost, seller notes, internal relationships, IMEIs and legacy source metadata. It is a metadata projection, not an availability or publication endpoint; the later public API must also apply product/listing visibility and canonical stock rules.

Authorized application writes atomically increment the MySQL `catalogue` publication version and record a minimal durable `catalogue.changed` event. Rollback removes the definition, usage and publication evidence together. No event consumer, network provider or new cache/service process is activated. Source-rehearsal inserts are isolated migration operations and intentionally do not publish catalogue events.

## Migration contract

`ProductImporter::import(runId, source, table, completeRow, sourceTimezone)` supports only POS `pos_master_data_options`, `pos_master_data_usages`, `products`, `stock_units`, and Website `products`. An explicitly marked `product_rehearsal` run must name the connected target database. The frozen `COLUMN_DESTINATIONS.json` and `TARGET_SCHEMA.json` remain the mapping contracts and must accompany a deployment using the importer outside the public web root.

The decoder rejects missing/unknown columns, invalid nullability/types/lengths, binary-float money, negative/overprecision money, unsupported timestamps and invalid source identity/timezone. It retains all mapped source columns and converts explicit UTC/Asia-Karachi timestamps to UTC. Role-qualified option actors and every non-null parent FK are resolved through the source-qualified identity map. Wrong option lists, invented categories, malformed metadata and product/outlet/identifier mismatches fail before a partial product can remain.

Identical row/timezone replay resolves its existing target mapping; changed input/timezone and database collisions quarantine without overwriting target edits. Historical unit acquisition/sale/invoice references are never nulled to make an import succeed: their mapped parent must exist and agree with product/outlet, otherwise the unit remains quarantined for the later dependency batch. Usage IDs are remapped according to their known entity type; unknown historical types require reconciliation.

Website `external_source=mobist-pos` and `external_id` are candidates only. The mapped POS product, source outlet, category in both record and metadata, and supplied SKU must agree. Missing/ambiguous/mismatched links and duplicate listings quarantine without creating products or stock. Accepted Website rows map to both listing and canonical product; legacy price/quantity/availability/sync timestamps stay in `legacy_*` listing fields and never overwrite canonical product price or stock. Slug/content/source metadata remain preserved for later content/API work.

This is a validated synthetic rehearsal primitive, not a private-data import or cutover. Source hashes/run manifests and reconciliation remain required before promotion. Quarantine evidence stores a reason and digest, not the private row payload. Do not seed over an existing source option collision, append identifiers, guess a parent, infer stock from Website cache or rewrite a financial snapshot to pass migration.
