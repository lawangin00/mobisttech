# mobiST Tech — enforced CI execution behavior

Canonical authority: `lawangin00/references/UNIVERSAL_EXECUTION_MODE.json`, `UNIVERSAL_EXECUTION_MODE_POLICY.md` v1.6 and `UNIVERSAL_CI_REQUEST_DISPATCH_POLICY.md` v1.1. This project inherits current universal rules through `docs/AI_PROJECT_COMMAND_REGISTRY.md`; historical GitHub-only rollout examples in that registry do not override the current mode.

- `LOCAL` Normal Chat and native `DIRECT_LOCAL` Work: routine code, browser, PHP, build and regression checks execute on the authorized local PC, and normal Git pushes generate zero GitHub Actions. A local PASS or a fresh source SHA is not authorization to repeat the same tests on GitHub.
- `GITHUB` Normal Chat: source-bound stage-request commits are required for hosted stage acceptance. In LOCAL/DIRECT_LOCAL, a separate hosted request is permitted only for an approved release/milestone/project-completion gate or a genuinely distinct independent verification, with exact prior owner/milestone authorization, local evidence and hosted-only need first recorded in the implementation ledger.
- `.github/workflows/ci.yml` and `.github/workflows/github-only-website.yml` are request-only. Their `tools/ci-mode-gate.py` preflight rejects unscoped manual events, invalid project/source/ref/surface and unjustified LOCAL routine requests before expensive test jobs. Do not add unconditional `workflow_dispatch` to these workflows.
- `.github/workflows/deployment-rehearsal.yml` remains a separately scoped, historically milestone-only Linux rehearsal. It requires explicit authorization, local-evidence and distinct-hosted-need inputs; its independent preflight requires the authorization and evidence references to occur in the checked-out project ledger before the expensive rehearsal job. This is not a substitute for routine main CI or permission for the execution controller to self-authorize a run.
- The gate can validate request format/source binding; it cannot authenticate the truth of arbitrary authorization prose. Before writing a request or starting a milestone rehearsal, the execution controller MUST independently verify owner authorization/legitimate milestone, exact current local test/ledger evidence, unique hosted necessity, project identity/branch and existing runs. If any check fails, leave verification pending and do not trigger CI.
- Regression command after safe local sync: `py -3 tools/ci-mode-gate.py --self-test`. Do not create a real hosted run just to test that routine LOCAL dispatch is blocked. Incident and detailed acceptance checklist: `docs/audit/MT-7.5_LOCAL_CI_DISPATCH_ENFORCEMENT_2026-09-24.md`.

This control reconciliation does not complete MT-7.5, change roadmap progress, authorize a new hosted test, reset local work, or alter legacy repository boundaries.

## Risk-based local test scheduling and exclusive fixture lifecycle (all stages)

Apply `docs/PROJECT_EXECUTION_EFFICIENCY_POLICY.md` before any future stage/family test decision. Routine local changes require affected focused and neighbor checks, NOT automatic full backend/Playwright or hosted reruns. Reuse current valid PASS with explicit unchanged-code/config/contract/environment rationale. Full joined regression remains mandatory at applicable family/stage closure, final release or a justified material cross-system impact. For mutable local test schemas, run setup, migration, tests, cleanup and verification sequentially under the same exclusive DB lock (`py -3 tools/run_isolated_test.py --db-id mobisttech_test@127.0.0.1:13306 --cwd backend -- <test command>`), OR prove independently equivalent isolation, including namespace and external process preflight. Never overlap independent PHP and Playwright suites on that database or reset unowned residual rows. The local lock is cooperative only and cannot detect direct runner commands or prove data ownership. No workflow trigger/dispatch or CI acceptance gate is weakened by this scheduling policy.
